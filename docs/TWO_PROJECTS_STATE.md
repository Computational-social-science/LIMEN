## 2. Inputs: declared, verified, not borrowed

Both projects carry an `inputs.json` and a `scripts/check_inputs.py`. The pattern is the
same in each, and it exists because neither project's inputs can be tracked in git:

| project | input | size | where |
|---|---|---|---|
| LIMEN | 136M Keystrokes participant files | 168,593 files / 17.6 GB | `LIMEN/external-data/Keystrokes/Keystrokes/files` |
| LIMEN | birkbeck, jwtd, cscd | 590 MB | `LIMEN/external-data/` |
| LIMEN | laya pinned snapshot | 846 MB | HuggingFace cache, pinned by `config/pin_laya.json` |
| kso | 136M Keystrokes participant files | 168,593 files / 17.5 GB | `keystroke-observatory/external-data/Keystrokes/Keystrokes/files` |
| kso | corpus metadata | 21 MB | `keystroke-observatory/external-data/Keystrokes/` |
| kso | corpus archive | 1.46 GB | `keystroke-observatory/external-data/Keystrokes.zip` |

**The defect the contracts were written for.** Both projects reached into a sibling
directory for inputs, and neither noticed because it worked:

* a clean clone of `keystroke-observatory` ran the full pipeline and hashed the corpus
  archive out of `E:\2026-AI4S\LIMEN\`;
* three LIMEN scripts resolved `external-data` as `REPO_ROOT.parent / "external-data"`,
  a *different* tree (1.1 GB) from LIMEN's own (21.4 GB), and worked only because both
  happened to hold the same three datasets.

Both are fixed, and both are now checked in two ways: the search ORDER must try the
project's own copy first, and the OUTCOME must not resolve to a sibling checkout.
